# 0006 — UI i18n: i18next, typed TS locale modules, profile language

- Status: accepted
- Date: 2026-10-17 (WB-59)

## Context

- Every UI string is hard-coded English. Vietnamese learners and supporters need a Vietnamese UI.
- The UI has no test runner, so a missing translation must fail at `tsc`, not at runtime.
- The language must follow the learner to another device.

## Decision

| Topic | Decision |
| --- | --- |
| Library | `i18next` + `react-i18next`. No detector package (the logic is about 15 lines) |
| Files | `src/i18n/locales/<code>/<namespace>.ts`, one module per namespace, `as const` |
| Key parity | `vi` modules are typed against `en` → a missing or extra key fails `tsc` |
| Typed keys | `src/i18n/i18next.d.ts` augments `CustomTypeOptions` → `t('unknown.key')` fails `tsc` |
| Resolution | Profile language (once per login) → `localStorage['wordbuddy-lang']` → `navigator.languages` → `en` |
| Persistence | Identity stores `User.PreferredLanguage` (nullable, format check only, no allow-list) |
| Not translated | Lesson, vocabulary, grammar, quiz content; user-entered text; server-generated English text (known limit) |
| API errors | `errors:codes` maps `ProblemDetails` codes to text; unmapped codes fall back to a translated generic message |

## Add a language

1. Create `src/i18n/locales/<code>/` with the same modules, typed against `en`.
2. Add one entry to `SUPPORTED_LANGUAGES` in `src/i18n/config.ts`.
3. No backend change.

## Consequences

- One new UI dependency pair.
- Every new UI string needs an `en` and a `vi` key; `npm run build` enforces it.
- Server-generated English text stays English until the backend returns codes only.
